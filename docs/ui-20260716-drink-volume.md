## 2. Design Thinking四问（B线，产品UI）

**Purpose**：让用户记录不满一杯的饮水量（半杯、一小口），解决"喝了几口但没喝完一杯，忘了打卡"的问题。使用者是坐在电脑前的上班族，操作频次约每30-60分钟一次。

**Tone**：Organic / soft。现有app用暖米色调+海边度假杯+水豚吉祥物，整体友善、治愈、不紧绷。新组件延续这个温暖随和的调性。

**Constraints**：Tauri桌面app，单HTML文件内联CSS/JS，固定340x620px窗口，纵向空间紧张，无UI框架。

**Differentiation**：次级选项不是冷冰冰的功能按钮，而是"可以不用那么精确"的友善暗示。用暖色填充而非边框线条，跟主按钮形成"同一家族但安静一些"的感觉，而不是"主+副"的机械层级。

## 3. Aesthetics Guidelines五条决策（B线）

| 维度 | 决策 | 理由 |
|------|------|------|
| Typography | 次级按钮13px weight 500，跟undo按钮同字号但略重 | 在主按钮（15px/600）和undo（13px/400）之间建立中间层级 |
| Color & Theme | 不引入新色相。次级按钮用#F2ECE1暖填充，hover转#E3F2FB。蓝色仅在交互瞬间出现 | 跟设置页.pill组件同色，保持暖调为主 |
| Motion | 只在active态用scale(.97)，不加入场动画 | 这两个按钮常驻可见，入场动画没有意义 |
| Spatial Composition | 两个pill并排居中，总宽度窄于主按钮 | 通过收窄宽度建立视觉从属关系 |
| Backgrounds | #F2ECE1暖色填充，跟进度条未填充段同色 | 让次级按钮安静地融进页面底色，不跟主蓝按钮争注意力 |

## 4. 信息层级方案

按钮区域（从主按钮到底部文字）的信息层级：

| 层级 | 元素 | 视觉权重 |
|------|------|----------|
| 第一层 | "＋ 喝了一杯（300ml）"主按钮 | 最大尺寸220x46px，#0E7CBE填充，白色文字15px/600，带阴影 |
| 第二层 | "半杯 150ml""一小口 50ml"次级pill | 较小尺寸，#F2ECE1填充，#3D342E文字13px/500，无阴影 |

| 信息层 | "下次喝水 14:30"提示文字 | 纯文字，#7A6E62，13px/400 |

层级区分靠三个维度配合：
- **尺寸**：220px宽 > ~100px宽 > ~100px宽
- **填色**：蓝色实心 > 暖色实心 > 无填充仅边框
- **阴影**：有 > 无 > 无

## 5. 布局结构

### 5.1 整体按钮区域布局（ASCII框图）

窗口宽度340px，按钮区域占底部约170px：

```
├──────────────── 340px ────────────────┤

│         [进度条标签行 "起点/过半/完成"]        │
│                  ↓ 20px                       │
│     ┌──────────────────────────┐              │
│     │  ＋ 喝了一杯（300ml）     │  46px高      │
│     └──────────────────────────┘  220px宽     │
│                  ↓ 8px                        │
│       ┌──────────┐ 8px ┌──────────┐           │
│       │ 半杯150ml │     │一小口50ml│  34px高   │
│       └──────────┘     └──────────┘           │
│                  ↓ 8px                        │
│           [↺ 刚才点错了]                       │
│                  ↓ 6px                        │
│           下次喝水 14:30                       │
```

| 元素 | 高度 | 间距 | 小计 |
|------|------|------|------|
| 进度标签下方间距 | - | 20px（原28px压缩8px） | 20px |
| 主按钮 | 46px | - | 46px |
| 间距 | - | 8px | 8px |
| 次级pill行 | 34px | - | 34px |
| 间距 | - | 8px | 8px |
| 撤销按钮行 | 30px（原32px微压缩） | - | 30px |
| 间距 | - | 6px（原10px压缩4px） | 6px |
| 下次喝水文字 | 16px | - | 16px |
| 底部留白 | - | - | ~11px |
| **合计** | | | **179px** |

间距变更汇总：
- `#drinkbtn` margin-top：28px → 20px（减8px）

### 5.3 水平布局

两个次级pill居中排列，中间8px间隔。每个pill宽度由内容撑开（padding: 0 14px），预计：
- "半杯150ml"：约90px
- "一小口50ml"：约95px
- 总宽度：90 + 8 + 95 = 193px，窄于主按钮的220px

居中对齐方式：flex容器，justify-content: center，gap: 8px。

## 6. 组件规格清单

### 6.1 次级饮水pill（新增，页面专属）

**命名**：`#subDrinkRow`（容器）、`.subpill`（单个pill按钮）

**复用关系**：视觉上参考设置页`.pill`的形态（pill形、#F2ECE1填充），但因为主页是ID选择器风格且按钮行为不同（设置页pill是选中态切换，这里是一次性点击动作），不直接复用设置页class，写成页面专属样式。

**视觉规格**：

| 属性 | 值 |
|------|-----|
| 高度 | 34px |
| 水平内边距 | 0 14px |
| 圆角 | 9999px |
| 背景色 | #F2ECE1 |
| 文字色 | #3D342E |
| 字号 | 13px |
| 字重 | 500 |
| 边框 | 无 |
| 阴影 | 无 |
| cursor | pointer |
| font-family | inherit |
| transition | all .15s（跟设置页pill一致） |

**四态规格**：

| 状态 | 背景 | 文字色 | 边框 | 其他 |
|------|------|--------|------|------|
| 默认 | #F2ECE1 | #3D342E | 无 | - |
| hover | #E3F2FB | #0E7CBE | 无 | - |
| active | #E3F2FB | #0E7CBE | 无 | transform: scale(.97) |
| disabled | 不需要（主按钮可用时次级也可用） | - | - | - |

**文字内容**：
- 左pill："半杯{cupMl/2}ml"，如"半杯150ml"
- 右pill："一小口50ml"（固定50ml，不随杯子容量变化）
- cupMl变化时左pill文字跟着更新（跟主按钮括号内数字同步更新机制一致）

**内容约束**：
- 半杯ml值范围：50-500（杯子容量100-1000的一半），不会导致文字溢出
- "一小口50ml"是固定文案，不存在超长问题
- 如cupMl为奇数（如自定义150ml），半杯值取整：`Math.round(cupMl/2)`

## 7. 交互与动效规范

### 7.1 次级pill点击

- 点击"半杯"：调用后端，增加 cupMl/2 毫升。水位动画、数字、进度条、副标题通过现有 `render()` 函数同步更新
- 点击"一小口"：调用后端，增加50毫升。同上
- 点击后撤销按钮变为可见（跟主按钮逻辑一致，`count>0` 时显示）
- 点击后提醒计时器重置（跟主按钮一致，CLAUDE.md明确要求"任意入口打卡都重置提醒计时"）

### 7.2 hover / active反馈

- hover：背景从#F2ECE1过渡到#E3F2FB，文字从#3D342E过渡到#0E7CBE。过渡时长.15s，跟设置页pill过渡一致
- active：scale(.97)，跟全app所有可点击元素一致

### 7.3 撤销行为

- 撤销始终撤销最后一次操作，不管是整杯、半杯还是一小口
- 这是后端逻辑，UI层面"刚才点错了"按钮行为不变，只是后端需要记录每次增加的具体量而非固定减一杯
- **实施提醒**：当前后端`undo_drink`可能按固定cupMl扣减。改灵活记录后，undo需要按最后一次实际增加量扣减。此条属后端改动范围，UI方案只提醒

### 7.4 prefers-reduced-motion

次级pill没有自动播放的动画，只有hover过渡和active缩放。缩放幅度极小（3%），不需要额外的reduced-motion处理。跟主按钮、撤销按钮同一做法。

## 8. 设计依据

| 决策 | 来源 |
|------|------|
| pill形状 + #F2ECE1填充 | 设置页`.pill`组件已有这个视觉模式，次级pill沿用同一形态语言 |
| 13px / weight 500 | 介于主按钮（15px/600）和撤销按钮（13px/400）之间，从项目现有字号阶梯取值 |
| 不加阴影 | 阴影在现有体系里只用于主操作按钮和窗口本身，次级操作不加 |
| hover用#E3F2FB | 设置页的`.step:active`和返回按钮hover已用这个浅蓝色作为交互反馈底色 |
| 文字色用#3D342E而非#7A6E62 | 对比度考量。#7A6E62在#F2ECE1上约4.2:1，低于WCAG小字4.5:1标准。#3D342E在#F2ECE1上约10.8:1，满足标准。设置页pill（#7A6E62 on #F2ECE1 at 14px）也有同样的对比度问题，但本次新增组件用13px更小字号，选择用更安全的主文字色 |
| scale(.97) active态 | 项目全局一致的点击反馈模式（主按钮、撤销按钮都用） |
| 常驻可见、不做展开/折叠 | 这是一个轻量桌面工具，操作频率高但注意力低。隐藏在展开菜单里会降低发现率，违背解决"忘了打卡"这个初衷 |
| margin压缩（-8/-4/-4） | 空间不够的硬约束决定。压缩分布在三处而非集中一处，避免某一处间距突然变窄 |

## 9. 工程正确性底线自检

| 检查项 | 本方案交代 |
|--------|-----------|
| 可访问性：对比度≥4.5:1 | 次级pill：#3D342E on #F2ECE1 ≈ 10.8:1 通过。hover态：#0E7CBE on #E3F2FB需验算（约3.8:1，但hover是瞬态且有颜色变化作为额外信号，不单独承载信息），focus ring见下条 |

## 11. 待决策项

1. **触控尺寸 vs 项目现状**：设计约束要求≥44x44px，但现有app的图标按钮（26px）、撤销按钮（~32px）、设置页step按钮（34px）都未达标。次级pill的34px高度与项目现状一致。如果要全面达标，需要全app统一调整，建议作为单独任务处理，不在本次改动里单独拉高次级pill造成视觉不一致。

2. **字体是系统字体**：frontend-design原则建议避开系统字体，但项目全部使用`-apple-system, PingFang SC`。这是一个Mac桌面工具app，系统字体在这个场景下是合理的（跟macOS原生控件风格统一）。如果想换有性格的字体，建议作为整体视觉升级的单独任务，不在单个组件改动里引入。

3. **设置页.pill的对比度**：设置页的.pill组件（#7A6E62 on #F2ECE1）在14px字号下约4.2:1，低于WCAG 4.5:1标准。本次新组件选择了更深的#3D342E文字色来规避，但设置页的既有问题建议另行修复。

4. **后端undo逻辑**：当前`undo_drink`可能按固定cupMl扣减。灵活记录需要后端记住每次增加的具体量（300/150/50），undo按最后一次实际量扣减。这是后端改动，需要code-writer一并处理。

## 12. 给code-writer的交付说明

### 扫描了哪些来源
- `app/src/main/index.html`：主页完整布局和样式
- `app/src/settings/index.html`：设置页的.pill组件模式、配色、交互方式
- 项目`CLAUDE.md`：v2设计方向、三个打卡入口的计时重置规则

### 复用了哪些token/变量/类/组件
项目无CSS变量体系，全部硬编码值。复用的具体值：
- 颜色：#F2ECE1（pill背景）、#3D342E（pill文字）、#0E7CBE（hover文字）、#E3F2FB（hover背景）
- 圆角：9999px（pill形）
- 字号：13px、字重500
- 动效：`.15s` transition、`scale(.97)` active

### 新增了哪些组件
- `#subDrinkRow`：次级pill的flex容器行
- `.subpill`：次级饮水量按钮（页面专属，写在主页`<style>`里）
- 对应两个button元素，一个半杯一个一小口

### 审美线路
B线（产品UI），加载了frontend-design SKILL.md。四问答案见第2节。五条决策见第3节。

### 实施注意事项

1. **间距压缩**：`#drinkbtn` margin-top 28→20px，`#undoRow` margin-top 12→8px，`#next` margin-top 10→6px。这三处改动是给新增行腾空间，改的时候注意不要影响进度条上方的间距。

2. **后端调用**：需要跟后端约定新的invoke命令。建议：
   - `invoke('drink_amount', { ml: cupMl/2 })` 半杯
   - `invoke('drink_amount', { ml: 50 })` 一小口
   - 或者复用现有`invoke('drink')`但传参指定ml数
   - 现有`invoke('drink')`不传参默认按cupMl加，看后端怎么改方便

3. **undo改动**：后端需要维护一个"最后一次操作的ml数"，undo时按这个数扣减，而非固定扣cupMl。

4. **render()更新**：主页`render(s)`函数里，半杯pill的文字需要跟随cupMl动态更新。在现有的`drinkbtn.textContent = '＋ 喝了一杯（'+cupMl+'ml）'`附近加一行更新半杯pill文字即可。

5. **HTML位置**：新的`#subDrinkRow`插在`#drinkbtn`和`#undoRow`之间。

6. **style位置**：`.subpill`样式写在主页`<style>`标签内，放在`#drinkbtn`相关样式后面。

7. **计时重置**：CLAUDE.md明确要求"任意入口打卡都重置提醒计时"。半杯和一小口的打卡也必须触发计时器重置，跟主按钮一致。
