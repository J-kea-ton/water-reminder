## 2. 审美方向

B线产品UI，延续v2方案已确立的方向，不重新定。

**Design Thinking四问（本次功能增量适用）**：

- **Purpose**：用户只喝了半杯或几口水时也能准确记录，解决一整杯记录粒度太粗导致数据不准的问题。使用者是久坐上班族，场景是随手点一下。
- **Tone**：延续v2软陶治愈，暖色奶油底+水蓝强调+Apple质感。
- **Constraints**：340px固定窗口宽度，按钮区最大可用宽约300px；不挤压杯子区和撤销/下次喝水区；主按钮是用户已有肌肉记忆的操作位。
- **Differentiation**：不适用（功能微调，非新页面设计）。

| 层级 | 元素 | 视觉权重 |
|------|------|---------|
| 第一层 | 主按钮「喝了一杯」 | 最大尺寸，蓝底白字，阴影，15px/600 |

## 4. 布局方案

提供两个方案，各有取舍，请拍板选一个。

### 方案一：双行布局（主按钮 + 下方辅助行）

主按钮独占一行，保持现有外观完全不变。下方紧跟一行两个辅助按钮。

```
              ┌──────────────────────┐
              │  ＋ 喝了一杯（300ml）  │    ← 主按钮 220×46px 不变
              └──────────────────────┘
                 8px
              ┌──────────┐  ┌──────────┐
              │ 半杯 150ml│  │一小口 50ml│   ← 辅助按钮 各106×36px
              └──────────┘  └──────────┘
                     8px间距
```

**尺寸规格**：

- 主按钮：220×46px，完全沿用现有样式不动
- 辅助按钮：每个106×36px，两个水平居中排列，总宽106+8+106=220px，与主按钮左右对齐
- 主按钮到辅助行间距：8px
- 辅助按钮之间间距：8px

**文案**：

- 主按钮：「＋ 喝了一杯（300ml）」（不变，ml数值跟随cupMl动态）
- 左辅助：「半杯 150ml」（ml数值 = cupMl/2，动态）
- 右辅助：「一小口 50ml」（固定50ml）

**垂直空间处理**：

辅助行新增占用：8px间距 + 36px按钮高 = 44px。为容纳这44px，调整以下间距（不挤压杯子区和撤销/下次喝水区）：

- 里程碑轨道到主按钮间距：28px → 16px（省12px）
- 主按钮到撤销行间距：12px → 8px（省4px，从主按钮下方算起是8+36+8=52px到撤销行）
- 下次喝水 margin-top：10px → 8px（省2px）
- 合计省18px，剩余26px缺口由窗口高度补：620px → 646px

**优点**：主按钮外观和位置完全不变，用户肌肉记忆零损耗；辅助选项在主按钮正下方，发现成本低。

**缺点**：窗口需要增高约26px；按钮区从一行变两行，视觉稍重。

---

### 方案二：单行三按钮横排

三个按钮排成一行，主按钮居中最大，辅助按钮分列两侧较小。

```
  ┌────────┐    ┌────────────────┐    ┌────────┐
  │ 一小口  │    │   ＋ 喝了一杯   │    │  半杯   │
  │  50ml  │    │               │    │ 150ml  │
  └────────┘    └────────────────┘    └────────┘
    68×42px    8px   148×46px     8px   68×42px
```

**尺寸规格**：

- 主按钮居中：148×46px，蓝底白字药丸
- 左辅助（一小口）：68×42px，描边药丸
- 右辅助（半杯）：68×42px，描边药丸
- 按钮间距：8px
- 总宽：68+8+148+8+68 = 300px
- 三个按钮垂直居中对齐

**文案**：

- 主按钮：「＋ 喝了一杯」（去掉括号里的ml，按钮缩窄后放不下；ml信息由上方大数字区承载）
- 左辅助上行：「一小口」13px
- 左辅助下行：「50ml」11px 弱化色
- 右辅助上行：「半杯」13px
- 右辅助下行：「150ml」11px 弱化色

**排列逻辑**：一小口（最小量）在左，一杯（主操作）居中，半杯（中间量）在右。主按钮居中保持视觉焦点和点击惯性。

**垂直空间处理**：不增加垂直占用，主按钮行高保持46px（辅助按钮42px矮于主按钮，居中对齐）。窗口高度不变。

**优点**：不增加窗口高度；三个选项一目了然，快速可达。

**缺点**：主按钮从220px缩到148px，文案需简化（去掉ml标注）；辅助按钮68px宽度较紧凑；整体按钮区视觉密度增加。

## 6. 交互与动效规范

### 6.1 辅助按钮hover/active

- hover态：边框和文字同时切到`#0E7CBE`蓝色，底色切到`#F0F8FC`淡蓝，150ms `ease`过渡。与现有撤销按钮hover一致的交互语言。
- active态：`scale(.97)` 按压反馈，与主按钮和撤销按钮一致。
- 过渡属性：`transition: border-color 150ms ease, background-color 150ms ease, color 150ms ease`

### 6.2 点击反馈

点击任一按钮（一杯/半杯/一小口）后的反馈流程与现有主按钮一致：

1. 按钮按压`scale(.97)`
2. 上方大数字更新（旧值淡出新值弹入，沿用v2设计稿第7.2节C组件的+1动效：`scale 1→1.1→1`，250ms `cubic-bezier(.34,1.56,.64,1)`）
3. 水位上涨（400ms `cubic-bezier(.4,0,.2,1)`）
4. 副行文字更新
5. 若触发半程/达标节点，勋章点亮+鼓励横幅

### 6.3 focus ring

所有按钮添加`:focus-visible`样式：`outline: 2px solid #0E7CBE; outline-offset: 2px`。与主按钮保持一致的focus ring色。现有代码未显式设定focus样式，本次新增按钮应补上，建议顺带给主按钮和撤销按钮也加上（作为待决策项提出，不强改现有按钮）。

### 6.4 prefers-reduced-motion

辅助按钮的hover过渡在reduced-motion下保留（150ms色彩切换不构成动画干扰）。active态的scale按压反馈也保留（瞬时反馈，非持续动画）。

## 7. 设计依据

| 决策 | 理由 |
|------|------|
| 辅助按钮用描边样式而非淡色填充 | 沿用项目已有的辅助按钮语言（撤销按钮的border+subtle bg），不引入新的按钮等级 |
| 辅助按钮文字色用`#3D342E`而非撤销按钮的`#7A6E62` | 辅助饮水按钮是高频操作入口，比撤销按钮的信息层级更高，需要更强可发现性。撤销是纠错动作用弱化色合理，饮水记录是主路径分支需要能看到 |
| hover态切蓝色边框+蓝色文字 | 沿用撤销按钮的hover逻辑（`.ic:hover{background:#F0E8DA}`是icon按钮的hover，撤销按钮hover切蓝边+蓝字），保持交互语言一致 |
| 方案一主按钮完全不动 | 用户对主按钮位置和外观有肌肉记忆，零修改是最安全的选择 |
| 方案二主按钮居中保持 | 即使缩窄，居中位置保证用户的点击习惯不受影响 |
| 辅助按钮药丸圆角而非小圆角 | 项目所有按钮（主/撤销）都用`9999px`药丸，不引入新圆角层级 |
| 方案一辅助行宽度对齐主按钮220px | 两行左右对齐产生整齐的视觉重心，不引入额外的宽度层级 |
| 方案二辅助按钮42px高（非44px） | 这是桌面app不是移动端，42px的鼠标点击区域充足；高度压一点与46px主按钮拉开层级差 |

## 8. 方案自检

### 反AI套路（B线 frontend-design条款）

1. 字体没踩Inter/Roboto/Arial：用项目既有的系统栈`-apple-system,"PingFang SC"`。通过。
2. 配色没用紫渐变白底：沿用奶油底+水蓝，新增按钮只用了项目已有的两个色（`#0E7CBE`蓝和`#E7DECF`边框）。通过。
3. 布局不是可预测的标准模板：就是按钮组排列，功能增量本身没有空间玩非常规布局，也不该为了避AI感硬搞花活。通过（不适用）。
4. 有context-specific character：按钮融在水杯+水豚的治愈系界面里，配色和圆角都是这个产品特有的暖调。通过。

### 工程正确性底线

| 条目 | 方案交代 |
|------|---------|
| 可访问性 | 主按钮白字在`#0E7CBE`上对比度≥4.5:1（v2已验证）；辅助按钮`#3D342E`文字在`#FEFDFB`底上对比度≈12:1达标；focus ring已在6.3节指定 |
| 触控 | 桌面app，主按钮46px，辅助按钮方案一36px/方案二42px，鼠标操作充足；相邻按钮间距8px≥8px底线 |
| 响应式 | 固定340px窗口，不做响应式多断点 |
| 动效 | hover 150ms过渡，active瞬时scale，在150-300ms范围内；reduced-motion已在6.4节交代 |
| 反馈与状态 | 每个按钮明确了默认/hover/active/disabled四态（5.1和5.2节） |
| 颜色不作唯一信息载体 | 按钮通过文字（半杯/一小口/一杯）+位置+尺寸差异区分，不仅靠颜色 |

## 9. 待决策项

1. **选方案一还是方案二**：方案一主按钮不动但窗口要增高约26px；方案二窗口不变但主按钮缩窄且文案简化。两个都能用，区别在于更看重肌肉记忆（选一）还是更看重窗口紧凑（选二）。
2. **半杯和一小口的计数逻辑**：当前系统用「杯」计数（今日3杯），点半杯算0.5杯还是只加ml不加杯数？如果算0.5杯，副行会显示「今日2.5杯」这样的小数。如果不加杯数只加ml，副行的杯数和ml总量会对不上。这是产品逻辑问题，UI方案两种都能承载，请拍板。
3. **撤销粒度**：点一小口后撤销，是撤销50ml还是撤销最近一次操作（可能是300ml）？现有撤销逻辑撤的是一整杯，加了分量记录后需要确认撤销的是最近一次操作对应的量。
4. **focus样式补齐**：现有主按钮和撤销按钮没有显式的`:focus-visible`样式。新增辅助按钮会加上focus ring，建议顺带给现有按钮也补上，但这属于改现有元素，请确认是否一起做。
5. **方案二主按钮文案**：去掉ml后文案变成「＋ 喝了一杯」。如果觉得用户需要看到ml数值，可以改为「＋ 一杯 300ml」（需要验证148px宽度下是否放得下，可能需要font-size从15px降到14px）。

## 10. 给code-writer的交付说明

- **扫描来源**：`app/src/main/index.html`（现有主页样式和结构）、`docs/ui-20260712-water-reminder-v2.md`（v2设计稿token体系，本方案所有色值/字号/间距/圆角的语义名和取值均源自此处）。
- **复用**：沿用现有`#drinkbtn`的样式作为主按钮基础（方案二仅改宽度和文案）；辅助按钮样式基于`#undoBtn`的描边逻辑，但文字色改深（`#3D342E`替代`#7A6E62`）、高度和宽度按方案调整。
- **新增组件**：两个辅助按钮（半杯、一小口），命名建议`#halfBtn`和`#sipBtn`，跟随项目既有的id命名风格。
- **页面专属 vs 公共**：三个饮水按钮都是主页专属组件，不需要抽为公共组件。
- **用的线和审美**：B线产品UI，延续v2软陶治愈方向，未做新审美决策。所有取值来自项目现有色彩和样式。
- **实施注意**：
  1. 辅助按钮的ml数值需动态：半杯 = `cupMl/2`，一小口固定50ml。JS里`render()`函数需要拿到`cupMl`来更新辅助按钮文案。
  2. 方案一需调整间距和窗口高度：track margin-top 26→16px，undoRow margin-top 12→8px，next margin-top 10→8px，窗口高度620→646px。
  3. 方案二需改`#drinkbtn`宽度从220→148px，并更新`render()`里的文案赋值逻辑（去掉ml后缀）。
  4. 三个按钮点击后都要调用后端drink逻辑，但传入不同的ml量。确认后端`invoke('drink')`是否支持带参数（如`invoke('drink', { ml: 150 })`），还是需要新增命令。
  5. hover过渡：现有`#drinkbtn`和`#undoBtn`的hover都没写`transition`属性（CSS :hover直接切色无动画）。新增辅助按钮会加150ms transition。如果一起补给现有按钮，改动量小（加一行CSS），但请确认（待决策项4）。
  6. focus-visible样式现有按钮都没有，新按钮会加上。如果统一补齐，每个按钮加一行`:focus-visible`声明。
